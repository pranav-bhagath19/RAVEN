# RAVEN Domain Model Specification

## 1. Overview

This document specifies the core domain entities of **RAVEN**.

### Fundamental Monetary Rule
All monetary values across all entities are represented as **integer minor units such as paise**. Storage types will be selected during implementation based on the chosen database and domain constraints. Floating-point values for monetary calculations are strictly prohibited.

---

## 2. Conceptual Entities

### 2.1 Merchant
- **Purpose**: Represents the business entity using RAVEN for revenue recovery.
- **Key Fields**: `id`, `name`, `currency` (ISO 4217), `created_at`, `status`, `policy_config`.

### 2.2 Customer
- **Purpose**: Represents the paying customer purchasing goods/services.
- **Key Fields**: `id`, `merchant_id`, `email`, `phone`, `name`, `created_at`, `communication_preferences`.

### 2.3 Order
- **Purpose**: Represents commercial purchase intent.
- **Key Fields**: `id`, `merchant_id`, `customer_id`, `amount` (minor units), `amount_paid` (minor units), `amount_due` (minor units), `currency`, `status`, `created_at`, `updated_at`.
- **Invariants**: `amount_paid + amount_due == amount`.

### 2.4 Payment
- **Purpose**: Represents payment lifecycle associated with an Order.
- **Key Fields**: `id`, `order_id`, `merchant_id`, `customer_id`, `amount` (minor units), `currency`, `status` (`CREATED`, `AUTHORIZED`, `CAPTURED`, `REFUNDED`, `FAILED`, `AMBIGUOUS`).

### 2.5 PaymentAttempt
- **Purpose**: Execution attempt for a payment across a gateway/network.
- **Key Fields**: `id`, `payment_id`, `attempt_sequence`, `payment_method_type`, `status`, `error_code`, `error_description`, `gateway_reference`.

### 2.6 PaymentMethod
- **Purpose**: Payment instrument used in an attempt.
- **Key Fields**: `id`, `customer_id`, `type`, `network`, `issuer_bank`, `last4`, `is_recurring_token`.

### 2.7 Subscription
- **Purpose**: Recurring payment schedule for ongoing service billing.
- **Key Fields**: `id`, `merchant_id`, `customer_id`, `plan_id`, `amount` (minor units), `billing_interval`, `status`, `consecutive_failures`.

### 2.8 FinancialEvent
- **Purpose**: Immutable raw input event (webhook payload, API event log) ingested by RAVEN.
- **Key Fields**: `id`, `event_hash`, `event_type`, `gateway_event_id`, `payload`, `occurred_at`, `received_at`.

### 2.9 RecoveryOpportunity
- **Purpose**: Identified revenue risk case flagged by RAVEN for analysis and recovery planning.
- **Key Fields**: `id`, `merchant_id`, `payment_id`, `amount_at_risk` (minor units), `risk_category`, `status`.

### 2.10 RecoveryAction
- **Purpose**: Candidate or executed recovery intervention generated by Recovery Planner agent.
- **Key Fields**: `id`, `opportunity_id`, `action_type`, `parameters`, `expected_recovery_value` (minor units), `agent_confidence`, `policy_decision`.

### 2.11 RecoveryOutcome
- **Purpose**: Formal financial verification outcome recorded by Verification Agent.
- **Key Fields**: `id`, `opportunity_id`, `action_id`, `is_recovered`, `recovered_amount` (minor units), `verification_method`, `verified_at`.

### 2.12 AuditEvent
- **Purpose**: Append-only audit record with controlled write access capturing operations across RAVEN.
- **Key Fields**: `id`, `trace_id`, `entity_type`, `entity_id`, `actor_type`, `action`, `payload_snapshot`, `created_at`.

### 2.13 DecisionTrace (Core Lifecycle Entity)
- **Purpose**: Comprehensive, queryable representation of an autonomous recovery decision lifecycle.
- **Key Fields**: `decision_id`, `recovery_opportunity_id`, `input_state_snapshot`, `evidence_references`, `root_cause_result`, `candidate_actions`, `value_estimates`, `policy_evaluations`, `selected_action`, `execution_result`, `verification_result`, `timestamps`.
